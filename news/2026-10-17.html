GitHub 许可证合规 GA：把依赖选择前移到合并门槛

GitHub Enterprise Cloud 新增企业级许可证策略和合并前检查；它也提供 API，让编码 agent 在推荐依赖前检测是否违反组织策略。

关键事件 · Open source license compliance generally available

GitHub 于 10 月 16 日宣布开源许可证合规功能 GA。组织可以建立企业级许可证策略，用规则集要求 PR 在合并前通过检查；对不合规依赖，维护者可替换依赖、调整策略或建立包例外，并由指定角色审核关闭请求。

为什么重要：发布同时增加了查询包是否符合策略的 API。这让 agent 的“推荐或引入依赖”可以在写入代码前受组织规则约束，而不只在事后扫描。

行动项：先盘点现有依赖和 SBOM，再把策略分为允许、需审批、禁止三档；给 agent 工具调用设置只读预检，异常走人工审批与审计日志。

边界：面向启用 GitHub Code Security 的 GitHub Enterprise Cloud 仓库；策略质量仍取决于许可证映射、例外流程和跨团队责任划分。
